# FS-169 two-notice identity gate

Follow-up to [the displayed notices audit](https://github.com/JeremyHennessy/FacilitySignal/commit/9d5cd19e78d626d94f8f5d1703fba03a67d92429), restricted to the two linked CMS PDFs on the single multi-document row. Both notices supplied a location, distinct case numbers, and a shared reference. Searches of their rendered PDF text for CCN, Certification Number, and Provider Number located no explicit label; this is a text-observation limitation, not a claim about unrendered document metadata. Neither a case identifier nor a shared reference is a CCN. A notice must qualify on its own, with no inherited identifier from another document.

The exact pinned approved hospital directory contained 5,435 records. Across all records, conservative exact site comparison found one address candidate for each notice (uppercase/whitespace, terminal street suffix, ZIP5, exact locality and state). That is address corroboration in a contemporary directory, not historic provider identity. Both notices therefore remain held for review; no provider link is inferred or published. There were no case or facility identifiers or rows retained in this audit.

The included offline gate allows a stronger review candidate only when the document has an explicitly labeled CCN, one matching directory record, and one corroborating address. An explicit match is still not treated as a historical event crosswalk. Run `python -m unittest discover -s tests -p test_review_cms_hpt_notice_identity.py` for positive and negative synthetic checks. No source register, app, or storage changes were made.
