# Modern HCRIS form archive expansion — initial report indexes

CMS documents the report, numeric and alpha-numeric relational files at https://www.cms.gov/data-research/statistics-trends-and-reports/cost-reports ; ResDAC describes the first-column report key and five-field child layout at https://www.resdac.org/articles/medicare-cost-report-data-structure . This stage qualifies official modern-form extracts (hospital and SNF FY2024, hospice, renal, FQHC, RHC and CMHC multi-year files) separately. All child rows are streamed and reconciled to report keys; only report keys, ordinal and per-report child counts are durably retained. Numeric values and alpha contents are NOT retained for these new forms; HHA FY2024's existing detailed archive is unchanged. Unrecognized shape counts are explicitly reported, not mapped to measures. Report indexes are not facility counts. Do not count screened child rows as archived source observations. The bound on source and expanded bytes is intentional; oversized or unavailable archives fail without pointer changes. Subsequent form-specific worksheet dictionary qualification and numeric-value partitioning are needed for full financial detail. Each successful job verifies SHA-256 and exact inventory before issuing a private completion receipt. No raw source archives, public packs, new resources or changes to existing pointers. Existing Azure costs apply. No ingestion claimed from source code alone.
