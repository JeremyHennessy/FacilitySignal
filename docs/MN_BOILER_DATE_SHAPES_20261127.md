# Minnesota boiler date shape check (research only)

Minnesota [registration statute §326B.958, subd. 3](https://www.revisor.mn.gov/statutes/2026/cite/326B.958) separates the location certificate's expiration from each listed object's last inspection. [§326B.99](https://www.revisor.mn.gov/statutes/cite/326B.99) separates insurer reporting and exemption conditions. DLI says insurance-inspected information is [loaded weekly and can lag](https://www.dli.mn.gov/workers/boiler-engineer/certificate-registration-boilers-and-pressure-vessels). The [legacy data dictionary](https://secure.doli.state.mn.us/ccld/data/boilerdatabasedescriptions.pdf) calls the corresponding old fields COMPLETED and BUS_LIC_EXP. The prior pinned-edition aggregate records the literal current headers Last_Inspection_Date and Expiration_Date; it does not publish date values.

The accompanying offline validator accepts two provisional calendar shapes, YYYY-MM-DD and U.S. M/D/YYYY, on synthetic examples. These shapes have not been observed in the pinned CSV here. It distinguishes date relative to the snapshot from dates relative to each other, marks same-day expiration unresolved, and keeps blank, unsupported and invalid data separate. No date difference is labeled overdue, compliant or currently operating. The adapter does not load its own inputs, verify a current certificate, or establish authoritative field equivalence across source editions.

The pinned ZIP bytes were not available for replay through the current access path. No inspection/expiration counts for the 81 higher-priority candidate addresses were established; no newer snapshot was substituted. For a later replay, verify the exact prior ZIP SHA-256 and member metadata, profile actual date shapes before counting, retain only aggregate observations, and report separately source rows and address-level mixed classifications.
