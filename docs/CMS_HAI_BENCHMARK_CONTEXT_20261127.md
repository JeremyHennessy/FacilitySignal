# FS-040 CMS HAI national-context qualification

The official [national benchmark catalog](https://data.cms.gov/provider-data/dataset/yd3s-jyhd) and [hospital measure catalog](https://data.cms.gov/provider-data/dataset/77hc-ibv8) both identify the November 12, 2026 release. The [October 2026 dictionary](https://data.cms.gov/provider-data/sites/default/files/data_dictionaries/hospital/HOSPITAL_Data_Dictionary.pdf) explicitly separates national benchmark, state, and hospital grains. Read the [CMS measure explanation](https://data.cms.gov/provider-data/topics/hospitals/complications-deaths) before interpreting SIRs, which compare observed to predicted outcomes in defined populations.

The indexed official national table displays and counts six rows. This review validated all six exact SIR measure/period keys. Each displays the benchmark reference of 1, not an observed percentage, nationwide event rate, or hospital score. The publisher hospital table metadata counts 172,332 rows, but this run validated only a prebounded extract: the first 24 displayed hospital rows, covering four complete HAI measure-family sets before a fifth group begins. No row was taken from that partial trailing family.

The offline benchmark gate compared exact measure identifiers and period boundaries. Three numeric hospital SIR rows had matching benchmark context; one was publisher-labeled unavailable and had a footnote. Twenty auxiliary measures (intervals, predicted and reported counts, exposure metrics) did not stand in for a SIR. Publisher comparison labels were preserved verbatim as categories, not reconstructed from point values; one value below 1 is publisher-labeled no different. Missing or suppressed values are not zero and no value is inferred from the presence of other metrics.

The checksum covers the transient minimal displayed projection only, not raw CSV bytes. Browser-rendered/indexed table evidence is enough for this scoped test, but does not qualify the complete hospital payload or confirm download integrity. No provider names/IDs, addresses, contacts, raw rows, site claims, risk score, app updates or Azure writes are retained. Any future qualified use should join exact provider IDs at the reporting-program grain, never multiply an organization-level result across campuses or attribute outcomes to a building, vendor, or infrastructure. The offline qualifier also supports a future bounded national CSV when a suitable exact response is available.

Tests: `python -m unittest discover -s tests -p test_qualify_cms_hai_benchmark.py`.
